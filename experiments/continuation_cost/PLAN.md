# v10–v13 모델의 CPU 비용 대조

v10의 마지막 fold 학습 중에 작성한 측정 계획이다. 정확도 선택 규칙이나 학습을 변경하지 않는다. v10–v13 검증과 학습 프로세스 종료 후 실행한다.

같은 내부 fold0의 학습768시행으로 만든 fine64, narrow64, RF100_fine, ET400_fine과 v12가 내부 결과로 정한 최종 개발 가중치의 결합을 비교한다. 추가로 바깥 fold0의 학습1,024시행으로 만든 두 XGB와 그 fold에서 내부 선택한 결합을 측정한다. 두 묶음의 학습 규모를 명시하며, 내부 모델 비용을 바깥 모델의 정확도와 결합해 배포 모델의 실제 비용이라고 부르지 않는다. 전체 개발1,536시행 재학습은 없다.

기존 비용 측정과 같은 개발 자료의256개200ms창(seed20261105)을 사용한다. 기존384시험은 제외한다. 모델당 새 프로세스, CPU6스레드, GPU 학습이 없는 상태에서 실행하며 다른 학습 프로세스와 GPU 사용 상태를 전후 기록한다. 모델 로드와 입력 읽기는 시간에서 제외한다. 특징 추출, 모델 호출, 전체 특징+scaler+확률 추론을 각각20회 예열 후200회 측정한다. 단일창 median/p95, 실제 joblib 바이트, 기존 fit 시간을 기록한다.200ms 신호 취득은 계산 지연에 더하지 않고 별도로 표시한다.

특징은 기존 수식과 동등성이 검증된 벡터화 채널 스펙트럼을 쓴다. fine905를 한 번 계산하고 narrow410열을 선택한다. 두 모델 결합도 특징을 한 번만 계산한다. 이 구현에서는 narrow 모델도 전체 세부 주파수 배열을 계산한 뒤 필요한 열만 취하므로 특징 추출 절감은 주장하지 않는다. XGB는 CPU inplace_predict, 숲은 predict_proba를 사용한다. 모두8개 확률을 출력한다. 모델 클래스 열, 캐시 특징, 저장된 평가 예측과 CPU 복원 결과를 비교한 뒤만 시간을 잰다. 모델과 예측은 private에 유지하고 공개 가능한 집계만 results에 쓴다.

측정 순서와 입력을 고정하며 결과가 느리다고 반복 선택하지 않는다. 모델 크기는 scaler를 포함한 직렬화 크기이고 메모리 사용량과 다르다. PC 부하와 스케줄링 영향을 받는 로컬 측정이며 실시간 시스템의 최악 지연 보증이 아니다.
