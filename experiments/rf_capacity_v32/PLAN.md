# 410개 특징에서 RF 분할 용량과 목표 구성을 비교

2026-10-22 UTC, 결과 열람 전 고정. 논문 대조는 `docs/PAPER_IMPLEMENTATION_COMPARISON.md`를 먼저 읽는다. 이 실험은 논문 RF의 정확재현이 아니다. 기준선 RF100/25TD는 강의 그대로 이미 완료됐으며 다시 실행하지 않는다.

가설: v13 RF는 905특징·직접8목표, v28은 410특징·64목표이지만 제한된 ExtraTrees였다. v28은 384잎 제한에 도달하고 학습 정확도 약92%에 그쳤다. 현재410특징에서 최적 분할을 선택하는 RF에 충분한 잎을 허용하면 두 실험과 다른 오류 구조를 학습할 수 있다. 직접8/64목표 비교로 기록 대응 학습 목표의 기여도 함께 확인한다. 이 가설은 개선을 보장하지 않는다.

입력200ms×5채널, hop100ms, 전19창, 전체개발1536시행/64기록, v10의 같은 내부768/256 및 바깥1024/512시행 ID를 유지한다. 추론에서 기록ID·사람ID·창위치·시행경계·과거/미래를 쓰지 않는다. 기존시험384시행은 새로 평가하지 않는다. 64목표는 사람×8클래스로 기록과 일대일 대응하며, 그 확률을 사람축으로 합쳐8클래스로 평가한다. 기록 공유·반복개발선택 한계는 유지한다.

RF 설정 하나: n_estimators=200, criterion=gini, max_depth=None, min_samples_split=2, min_samples_leaf=1, max_features=.5, max_leaf_nodes=None, bootstrap=True, max_samples=None, class_weight=None, ccp_alpha=0, random_state=42, n_jobs=6, warm_start=False. 나머지는 설치된 sklearn1.7.2 기본값, 전체 get_params 저장. 각 분할의 모든 학습창을 fit에 제공한다. RF 자체 bootstrap은 복원추출이며 외부의 시행/창 축소와 구분한다. scaler는 학습에서만 fit한다. CPU sklearn 구현이므로 GPU 강제 사용은 하지 않는다.

후보는 direct8와 latent64 두 개. 각 fold에서 기존 v25 확률에 `0.9*기존+0.1*RF`로 결합한다. 비중 탐색 없음. 내부 정답이 기존보다 최소10창(4864창의0.2056%p) 많고, 모델+scaler의 총 저장크기(기존 구성 포함)가 기존의3배 이하인 후보만 자격이 있다. 가장 많은 정답, 동률이면 총 바이트가 작은 후보, 다시 동률이면 direct8 순서로 선택한다. 단독 RF 정확도는 보조이며 선택에 사용하지 않는다. fold별 선택은 해당 내부 결과로만 결정한다. 다른 fold 점수의 합을 선택에 쓰지 않는다. 내부6fit를 마친 뒤 선택파일을 고정하고 선택된 fold에만 바깥 RF를 학습한다. 새6–9fit, 예상CPU수분~20분. 실제시간과크기를 기록하고 결과가 낮아도 트리수/특징비율/비중을 사후 변경하지 않는다.

모든 모델을 다시 불러와 확률·확률열·클래스지원·학습전용scaler·분할ID·원본해시·8클래스 수동지표·원래19창을 검사한다. 첫 실행 이전 계획과 코드 해시를 저장한다. 바깥 선택표는 모든1536시행을 정확히한번 평가한다. 창을 독립 표본으로 가정한 신뢰구간은 계산하지 않는다. 입력시간범위를 늘린 v23과 현재 최고v25를 덮어쓰지 않는다.

열세 내부 후보는 학습시간/크기/복원까지만 기록하고 긴 지연 측정은 생략한다. 실제 채택 후보가 있으면 대표 바깥fold의 동일380창에서 특징+전체확률 추론비용을 기존모델과 함께 측정한다. 기존 라벨전용 호출생략 비용과 섞지 않는다. 평가384시행은 재사용하지 않는다. 외부 게시·업로드는 금지 상태다.
