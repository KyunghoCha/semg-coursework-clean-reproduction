# 현재 창의 두 표현을 결합하는 후속 개선

v9와 v8은 같은 평가창 29,184개 중 1,212개에서 예측이 달랐다. 전체 표현만 맞힌 창 479개와 좁은 표현만 맞힌 창 535개가 있어 오류가 완전히 같지는 않았다. 두 모델 모두 틀린 창은 2,448개다. 이 정답을 아는 사후 집계를 구현 가능한 선택 규칙이나 달성 정확도로 표시하지 않는다. 다음 검증은 현재 창의 확률만 합쳐 상보성이 실제 성능으로 이어지는지 검사한다.

이 계획 시점에는 v10의 첫 내부 fine64와 narrow64 학습을 마쳤고 첫 drop_two64를 실행 중이며 바깥 평가는 아직 없다. v10 후보·선택 규칙은 바꾸지 않는다. v12는 별도 결과로 남기고 이미 개발에 사용한 자료라는 제한을 유지한다. 기존 384시행 시험에는 접근하지 않는다.

## 입력과 결합 규칙

현재 200ms·19창·5채널·원래 crop을 유지한다. 모델은 v10의 fine64와 narrow64뿐이다. 각 모델의 64확률을 사람 축으로 합쳐 8클래스 확률 p_f와 p_n을 만든다. p=(1−a)p_f+a p_n에서 a 후보를 [0, .25, .5, .75, 1]로 미리 고정한다. 과거·미래 창, 시행 다수결, 피험자 ID와 평가 정답을 예측 입력에 쓰지 않는다. 온도 보정이나 추가 보정기를 함께 튜닝하지 않는다.

각 v10 바깥 fold의 기존 내부 768시행 학습·256시행 선택 예측으로 a를 고른다. 정답 창 수 최대, 정확히 동점이면 모델 하나만 쓰는 끝점, 그다음 필요한 입력 특징 수가 적은 조건, 그다음 .5와 가까운 값, 마지막은 작은 a를 택한다. 끝점 a=0은 905특징 한 모델, a=1은 410특징 한 모델이며 내부값은 두 모델과 전체 905특징이 필요하다. 3개 내부 선택 결과의 합산 정답 수로 최종 개발 a를 따로 정하고 바깥 점수는 선택에 쓰지 않는다.

해당 바깥 학습 1,024시행에서 두 모델을 준비한다. v10이 이미 같은 분할·설정으로 만든 모델은 해시를 확인해 재사용한다. 없는 narrow64만 새로 학습하므로 추가 학습은 0~3회다. 선택이 끝점이면 그 모델의 점수와 비용을 사용한다. 비교를 위해 고정 50:50과 각각의 끝점도 전부 보고하며, 바깥 최고값으로 다시 선택하지 않는다. v11 성분 제거 대조를 마친 뒤 실행한다.

## 평가·비용·한계

3개 바깥 fold의 전체 창 정확도, macro F1, 각도/동작 정확도, log loss와 multiclass Brier 점수를 보고한다. Brier는 창마다 8클래스 (확률−one-hot)²의 합을 낸 뒤 평균한다. ±는 fold 표준편차(ddof=0)다. 원본 확률 열, trial ID, train-only scaler와 fold의 일치, 결합 합계1, 끝점 동등성, 동점 선택 규칙을 검사한다. 혼합의 개별 확률·예측은 로컬 비공개에만 둔다.

혼합을 선택하면 총 51,200트리와 두 scaler/모델을 보관한다. 같은 현재창 특징은 한 번 계산하고 두 모델 추론을 수행한다. 크기는 실제 두 모델 바이트 합으로, 지연은 뒤의 별도 안정된 CPU/GPU 측정으로 확인한다. 신호 수집 길이는 200ms로 같고 미래 대기는 추가하지 않는다. 크기·지연 증가에 비해 개선이 작거나 없으면 그 실패를 기록한다. 임의의 크기 상한으로 정확도 목표를 낮추지 않는다.

이 내부/바깥 구분은 이번 a 선택 절차 안의 분리다. 특징 설계와 과거 진단은 개발 자료를 보았고 기록도 공유한다. 새 독립 자료나 논문 동등 평가가 아니다. 초기창 기록 대조에서 나타난 조건 의존 가능성을 이 결합이 해결한다고 주장하지 않는다.

근거: scikit-learn의 [확률 기반 voting 설명](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.VotingClassifier.html)은 확률의 가중 평균을 설명한다. 여기서는 저장된 확률에 같은 산술을 직접 구현하고 분할 밖 학습이나 자동 재학습을 하지 않는다. 확률 결합이 잘 동작할지는 별도로 검증할 가설이다.
