# GPU 호출 비용의 원인 분리

첫 통제 측정에서 64개 목표 모델의 DMatrix 경로는 단일 창 전체 처리 중앙값이 CPU 4.26ms, GPU 252.12ms였다. 이 차이를 GPU 하드웨어 자체의 한계로 단정하지 않는다. [XGBoost 3.0 공식 문서](https://xgboost.readthedocs.io/en/release_3.0.0/prediction.html)는 `inplace_predict`가 DMatrix 생성을 생략하며 GPU 배열 입력을 지원한다고 설명한다. 입력 변환과 호출 경로의 영향을 따로 검사한다.

기존 17개 모델의 30개 장치 조합을 먼저 모두 측정하고 보존한다. 추가 비교는 강의 XGB400, 7차 cross400, cross800의 저장 모델 3개를 같은 256개 입력으로 CPU/GPU 각각 실행한다. 학습·후보 선택·시험 평가는 추가하지 않는다. CPU는 float32 NumPy 입력, GPU는 매 호출마다 float32 변환과 CuPy의 host→device 복사, inplace_predict, 확률의 CPU 반환을 모두 포함한다. 미리 GPU에 올려 놓은 입력의 시간으로 전체 처리 시간을 대체하지 않는다.

같은 6스레드 상한, warmup20회 뒤 batch1 200회, warmup5회 뒤 batch256 30회를 유지한다. 특징·scaler·모델·전체·문맥 추가 시간을 분리하며 GPU 시간은 호출 앞뒤 동기화한다. 기존 경로와 확률을 허용오차 안에서 비교하고, 모든 256개 분류 예측은 정확히 일치해야 한다. 경로별 결과와 메모리 관측을 별도 파일에 저장한다. 최초 경로 측정값을 덮어쓰지 않는다.

CuPy는 [공식 설치 문서](https://docs.cupy.dev/en/v13.6.0/install.html)와 [PyPI의 CUDA12용 13.6.0 배포](https://pypi.org/project/cupy-cuda12x/13.6.0/)를 확인했다. Python3.13, NumPy2.3과 CUDA12.8이 지원 범위에 있다. 사용자가 승인한 공식 패키지 설치 범위에서 새 격리 가상환경에만 준비한다. 기존 시스템·이전 프로젝트 환경은 바꾸지 않는다. 설치와 추가 측정은 현재 벤치마크를 마친 뒤 수행한다.


8차가 완료된 뒤 호출 경로 대조를 실행하면 동일 고정 분할의 fine400 대표도 추가한다. 이 확장은 해당 후보의 결과를 보기 전에 정하며, 결과가 낮더라도 측정한다. 이때 기존 17개와 fine400의 DMatrix 측정을 모두 보존하고 4개 모델·8개 장치 조합의 inplace 경로를 추가한다.

## 실행 전 비용 범위 수정 (2026-10-21 01:17 UTC)

원래 32개 장치 조합과 v8 검증을 모두 완료한 뒤, 후속 측정이 개선 실험을 오래 막지 않도록 범위를 줄였다. 아직 inplace 측정값은 하나도 보지 않은 시점의 수정이다. 기존 모델 4개·장치 8조합은 유지한다. 이미 검증한 특징·scaler·문맥 갱신 시간은 다시 측정하지 않고 모델과 전체 처리만 비교한다. 단일 창은 warmup 20회 뒤 100회, batch256은 warmup 5회 뒤 10회로 고정한다. 단일 창 p95는 표본 100개의 경험적 분위수이며 정밀한 꼬리 지연 보증이 아니다. 기존 DMatrix 200/30회 결과는 그대로 보존하고 두 경로의 서로 다른 반복 수를 명시한다. 모델·데이터·출력 일치 검증·동기화·스레드 조건은 바꾸지 않는다.
