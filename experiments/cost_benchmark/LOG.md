# 기본 비용 비교 결과

첫 측정 묶음은 2026-10-21 00:19:13–00:57:26 UTC에 순차 실행했다. 17개 대표 모델의 30개 장치 조합, 240개 시간값 묶음을 검증했다. 단일 창의 여섯 항목은 각각 warmup20회 뒤 200회, batch256의 두 항목은 warmup5회 뒤 30회다. 타이머 원값에서 중앙값·p95·총 시간 기반 처리량을 다시 계산했다. 같은 입력 256개에서 CPU/GPU 분류 결과가 일치했다. 이 검사는 전체 평가창의 장치별 동등성 검사를 대신하지 않는다.

코어 라이브러리 상한과 RF/XGB의 스레드는 6으로 고정했다. SVC 자체는 단일 스레드 구현이다. GPU는 타이머 앞뒤 cudaDeviceSynchronize의 반환 코드를 확인했다. 모델 시간에는 DMatrix 생성, GPU 전송, CPU 확률 반환과 64→8 확률 합산을 포함한다. 그래픽 데스크톱은 실행 중이었다. 측정 시작·끝에 다른 GPU 계산 프로세스는 없었고, CPU 프로세스 상태는 비공개 로그에 보존했다. CPU 순간 경합이 전혀 없었다고 주장하지 않는다.

## 같은 비교 안에서의 절충

- 5차의 8→64개 학습 목표는 80.43→85.37%, 트리 3,200→25,600개, 대표 크기 11.58→41.81MB였다. CPU 전체 중앙값은 1.94→4.26ms로 늘었다. 이 비교는 목표 수와 트리 수도 함께 바뀌었다.
- 6차의 동일 25,600트리에서는 직접 8개 목표가 83.82%·53.68MB·CPU 5.03ms, 64개 목표가 85.58%·41.72MB·CPU 4.28ms였다. 교차 특징 추가는 88.39%·38.71MB·CPU 5.85ms였다. 최종 조건은 더 작고 정확하지만 CPU 특징 추출 시간이 늘었다. GPU의 같은 경로에서는 교차 조건이 세 조건 중 정확도·크기·전체 지연에서 모두 유리했다.
- 7차에서 400→800회는 +0.5482%p, 대표 크기 38.84→60.37MB, CPU 전체 5.93→7.22ms였다. GPU DMatrix 경로는 244.42→407.05ms였다. 추가 정확도와 비용을 함께 제시하며 큰 모델을 무조건 우선하지 않는다.
- 4차 내부 비교의 155특징 대안은 79.73%, 전체 240특징은 79.79%였다. 대표 CPU 전체 시간은 2.24/3.10ms, 크기는 19.56/19.46MB였다. 특징을 줄였다고 저장 크기까지 줄지는 않았다. 이 수치는 내부 검증 평균이며 바깥 평가와 섞지 않는다. SVM quantile 조건은 73.56%·57.75ms였고 scaler만 중앙값 53.75ms였다.

정확도는 해당 분할 전체의 집계이고, 비용은 첫 분할의 저장 대표 모델을 측정했다. 크기는 scaler를 포함한 실제 바이트를 십진 MB로 바꿨다. 경험적 Pareto 표는 같은 평가 그룹과 장치 안에서만 계산했으며 통계적 유의성 검정이 아니다.

## 구조와 메모리

7차 400회 모델은 25,600트리·646,510노드·336,055말단값·310,455분할 임계값, 800회는 51,200트리·783,950노드·417,575말단값·366,375분할 임계값이다. RF100은 1,371,220노드, 저장된 노드별 클래스 값 10,969,760개, 175.56MB다. SVM은 지지벡터와 계수 수를 별도로 기록했다. 서로 다른 구조를 같은 의미의 단일 파라미터 수로 바꾸지 않았다.

400/800회 CPU 측정 프로세스의 생애 최대 RSS는 각각 약 591/750MiB였다. Python과 라이브러리·입력·모델 로드를 모두 포함하며 모델만의 peak RAM이 아니다. GPU 실행의 두 관측 시점 VRAM은 166MiB였다. CPU 예측에서도 CUDA 모델을 읽으며 생긴 context의 148MiB가 관측됐다. 이는 실제 예측 장치가 CPU임을 확인한 결과와 구분한다. 이 두 시점은 순간 peak VRAM이나 학습 peak를 나타내지 않는다.

최초 묶음에서 저장 모델 44개의 크기·트리 수와 대표 17개의 상세 구조를 읽었고, 총 264개 학습 시간 기록을 집계했다. 이 중 4개는 과거 내부 모델을 비용 측정용으로 복원한 fit이다. 초기 300ms 선택 모델도 크기 목록에는 포함하고 200ms 추론 비교에는 섞지 않았다. 저장하지 않은 후보의 모델 크기를 추정해 채우지 않았다. fit 시간은 단계별로 scaler 포함 범위와 자원 경합이 달라 정의를 표에 붙였다.

## 다음 판단

현재 경로의 GPU 지연은 공식 inplace_predict로 DMatrix 생성 비용을 분리해 확인한다. 모델·신호·입력 256개·반복 수를 유지하고 원래 결과는 보존한다. CPU 교차 특징 추출 2.83ms가 모델 2.60ms보다 길어 같은 수식의 벡터화도 따로 검증한다. 정확도 개선용 v8은 기본 비용 측정을 끝낸 뒤 시작했다. 새 학습과 통제 추론 측정을 동시에 실행하지 않았다.

신호 취득은 첫 200ms, 과거 다섯 창이 모두 쌓인 뒤의 정보량은 600ms다. 첫 창부터 출력하므로 미래 대기는 없으며, 알려진 시행 경계에서 reset한다. 첫 출력의 신호 종료는 mark+1.7초, 완성된 문맥은 mark+2.1초다. 계산 시간과 별개이며 연속 동작 전환의 실제 응답 지연은 측정하지 못했다.

## 세부 파워 모델과 기본 비용 완료

v8까지 18개 대표·32개 장치 조합을 완료하고 256개 원시 시간 묶음의 중앙값/p95/합을 재계산했다. v8 대표는 36.339488MB, CPU 전체 6.1037/7.4888ms, GPU 전체 232.9461/249.2245ms였다. 저장 모델 47개, 관측 학습 시간 267개 기록 중 4개는 과거 모델 비용 복원이다. 원래30개 측정 파일은 보존했다.

## 호출 경로 비교와 실행 복구

새 격리 환경에 공식 CuPy13.6.0을 설치했다. 핵심 패키지 버전과 XGBoost 공유 라이브러리 SHA-256은 원래 환경과 일치했다. TITAN Xp의 compute capability 6.1과 실제 CuPy CUDA runtime12090을 확인했다. 모델·환경 설정은 `inference_environment.json`에 있다. 기존 시스템과 이전 프로젝트 환경은 바꾸지 않았다.

실행 전 사용자 요청을 반영해 중복인 특징·scaler·문맥 측정을 제외했다. 단일 창은 warmup20회 뒤100회, batch256은 warmup5회 뒤10회로 고정했다. 원래 DMatrix200/30회 결과를 덮어쓰지 않았다. 6/8조합 후 실행 프로세스가 종료된 것을 확인했으며 원인은 미확인이다. 저장된 결과·확률·원시 시간을 검증해 그대로 보존하고 마지막2조합만 재개했다. 최종 8/8조합과 이전 경로를 합쳐 96개 시간 묶음을 재계산했다. 256개 고정 입력에서 모든 분류 예측은 동일했다.

GPU 전체 중앙값은 cross400 244.42→174.61ms, cross800 407.05→301.54ms, fine400 232.95→168.45ms였다. 복사와 CPU 확률 반환을 포함한 inplace 경로가 줄어들었지만 CPU보다 느렸다. fine400 inplace에서 CPU batch1은 5.97ms, GPU168.45ms였고 batch256 전체 처리량은 CPU3212.85창/s, GPU1017.32창/s였다. 배치를 모으는 대기시간은 여기에 들어 있지 않는다. 단일 스트림의 100ms 이동과 200ms 수집 길이를 계산 처리량과 구별한다. 서로 다른 시점의 경로 비교이므로 작은 차이를 통계적 우위로 주장하지 않는다.

## 동일 수식의 벡터화

전체36,480창에서 원래/벡터화 교차 특징 최대 차이는4.44e-16이고 float32 값은 전부 같았다. 세 대표 모델 모두 개발29,184창을 scaler 변환한 뒤에도 float32 값이 같았다. v8의 세 모델에서는 모든 OOF 분류가 CPU/GPU에서 같았고 확률 최대 차이는1.1921e-7이었다.

같은 모델·입력을 번갈아200회씩 측정한 CPU inplace 비교에서 fine400의 특징 중앙값은3.1920→1.8943ms, 전체 중앙값은6.3685→4.8793ms, 전체p95는8.9045→6.5058ms였다. cross400 전체5.7338→4.3706ms, cross800 6.8790→5.5685ms였다. 12개 시간 묶음을 독립적으로 재계산했다. 원래32조합의 비용표를 바꾸지 않고 쌍 비교 결과를 별도로 남겼다. 새 학습·시험평가·분류 기준 변경은 없다. GPU 벡터화 전체 비용은 측정하지 않았다.
