# 교차 특징 계산의 벡터화

원래 400특징의 CPU 추출 중앙값 2.83ms가 같은 모델 추론 2.60ms보다 길었다. 정의를 바꾸지 않고 8개 대역×10개 채널 쌍의 Python 반복을 8개 대역의 행렬 계산으로 바꾼다. 원래 부동소수점 합 순서 차이가 있을 수 있으므로 합성 신호와 원본 전체 36,480창에서 수치 차이를 검사한다. XGB가 받는 float32 변환 결과까지 완전히 일치하는지 확인하고, 다르면 원래 모델의 실제 예측을 추가 대조하기 전에는 동등한 실행 경로라고 부르지 않는다. 신호 구간·특징 공식·임계값·모델·분할은 바꾸지 않는다.

검증과 비용 측정은 진행 중인 벤치마크 뒤에 실행한다. 원래 경로의 결과를 보존하며 같은 입력 256개, 6스레드 상한, warmup20회와 200회 반복으로 CPU 특징 추출과 전체 처리 중앙값/p95를 추가 비교한다. 측정하지 않은 GPU 전체 지연으로 일반화하지 않는다. 이 단계에는 새 학습이나 시험 평가가 없다.

추가 비교에서는 같은 모델·입력의 원래/벡터화 경로를 한 쌍으로 측정하고 실행 순서를 번갈아 균형을 맞춘다. 각 경로 20회 warmup 뒤 200회를 유지한다. 모델 호출은 CPU inplace 경로로 같게 둔다. 세부 파워 후보도 완성되면 같은 방식으로 포함한다. 원래 고정 벤치마크와 새 쌍 비교의 시간을 섞어 차이를 계산하지 않는다.
