# 측정 구현 확인

GPU 시간은 CUDA runtime의 `cudaDeviceSynchronize()`가 성공했을 때만 기록한다. 공식 [CUDA Runtime API 문서](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__DEVICE.html)는 이 호출이 장치 작업 완료를 기다린다고 명시한다. 실제 설치된 CUDA 12 runtime 라이브러리를 불러 사전 실행에 성공했다. 문서 링크의 최신 버전과 설치된 runtime 버전을 혼동하지 않는다.

추론은 모델별 새 프로세스에서 실행하며 실제 threadpool 상한도 결과에 남긴다. GPU 계산 프로세스는 시작과 끝에 확인하고 다른 계산 작업이 있으면 중단한다. CPU 프로세스별 상태와 GPU 사용률·클록·온도·전력은 측정 전후 비공개 로그에 남긴다. 이 기록은 측정 구간 전체를 표본화한 자원 peak가 아니다. 그래픽 데스크톱은 계속 실행된다.

단일 창 추출과 저장 특징은 실제 개발 창 8개에서 대조했다. 905개 세부 파워 확장도 같은 검사에 통과했다. 새 확장의 모델은 해당 개발 비교를 검증한 뒤 기존 측정 파일을 보존하고 CPU/GPU 두 항목만 추가한다. 전체 요약은 같은 평가 분할끼리 다시 만든다.

CPU 실행도 CUDA로 저장된 XGB를 읽는 과정에서 GPU context를 만들 수 있으므로, 장치 설정과 별도로 해당 PID의 관측 VRAM을 두 시점 모두 기록한다. CPU 예측은 booster의 실제 device=cpu를 확인한다. GPU 실행에서 자기 PID의 메모리를 관측하지 못하면 측정을 완료한 것으로 처리하지 않는다.

`ps`의 CPU 백분율은 프로세스 생애 평균이며 측정 구간의 순간 CPU 사용률이 아니다. 이 기록만으로 다른 CPU 작업이 전혀 없었다고 주장하지 않는다. GPU 계산 프로세스의 시작·끝 검사와 남아 있는 그래픽 작업도 관측 범위대로 설명한다. 첫 예측의 신호 종료는 mark+1.7초, 과거 다섯 창이 모두 채워지는 시점은 mark+2.1초다. 이 신호 대기와 실행 시간은 서로 다른 비용이다.
