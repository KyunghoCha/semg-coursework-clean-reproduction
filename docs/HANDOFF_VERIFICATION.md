# 인계 후 독립 검증과 실행 범위

2026-10-21 UTC. 동일 clean 프로젝트의 코드·캐시·결과를 이어서 사용했다. 이전 프로젝트 결과나 모델을 병합하지 않았다. 인계 당시 v10 PID1872308이 학습 중이어서 중복 실행하거나 종료하지 않았다.

## 초기창 2.60%의 재검증

원본 파일명 규칙으로 1,920개 레이블을 별도로 계산해 메타데이터와 기본 레이블 배열의 일치를 확인했다. 개발1,536시행은 각 클래스192개이고, 원래384시험 시행은 이 대조에서 제외됐다. 두 종류의4-fold 분할도 실험의 helper를 호출하지 않고 다시 구성해 저장된 ID와 비교했다.

| 검사 | 결과 |
|---|---|
| 시행 분리의 클래스 지원 수 | 학습144 / 평가48, 모든 fold·8클래스 |
| 기록 분리의 클래스 지원 수 | 학습139–148 / 평가44–53, 누락 클래스0 |
| 기록 분리의 클래스별 기록 수 | 학습6 / 평가2 |

| 초기창 특징 | 제공200표본에서905특징 재계산 일치 |

정수 혼동행렬에서 기록 공유는 **1,249/1,536=81.3151%**, 기록 분리는 **40/1,536=2.6042%**로 다시 계산됐다. 따라서 이번 검증 범위에서 클래스 누락·레이블 파싱·확률 열 순서 오류는 이 차이의 원인으로 확인되지 않았다. 각 클래스의 평가 지원 수를 합치면 두 프로토콜 모두192개다. 기록 분리 fold 크기는 달라서 fold 단순 평균2.6029%와 전체 합산2.6042%를 구분한다.

이는 초기200ms에 남은 분류 정보가 다른 사람×조건 기록에서 유지되지 않았다는 관측이다. 각 사람×조건당 기록이 하나뿐이므로 기록 특성과 그 조합의 변화가 얽혀 있다. 모든 학습 부분에8클래스가 남았다는 사실은 이 분포 변화를 없애지 않는다. 이 결과만으로 신호를 잡음으로 판정하거나, 강의의 활동 구간19창 평가를 기록 분리로 대체하지 않는다.

이전 초기창90.43%는 활동 구간에서 학습한 v8의64개 목표 OOF 모델을 초기창에 적용한 값이다. 이번81.32/2.60% 대조는 초기창에서 학습한 직접8클래스 모델이다. 이 서로 다른 실험 사이의 차이를 기록 분리 효과로 계산하지 않는다.

현재 코드가 제공 CSV의200표본 밖을 새로 참조하지 않는 것은 검사했지만, 제공 CSV를 만든 필터의 실제 위상·경계·미래 참조는 검증하지 못했다. mark+0–0.2초가 생리적 휴식인지도 미확인이다. 자세한 구분은 [시간 참조 범위](TEMPORAL_SCOPE.md)에 있다.

## 이후 실행과 판정

v10의 기존 후보·내부 선택·바깥 평가 규칙을 유지한다. 완료 후 저장 모델·확률·scaler·분할·선택을 검증한다. 이미 등록된 v11 정현파 성분 제거3회, v12 현재창 확률 결합, v13 두 숲 후보의 고정 대조를 순서대로 수행한다. 실패·악화 결과도 남기며 기존384시험은 추가 평가하지 않는다. 새로운 독립 외부 시험을 확보했다는 주장은 하지 않는다.

기본 파이프라인과 기록 분리·선택·정현파 투영·확률 결합·숲 선택의 벡터화 특징까지 필요한 단위검사23개를 통과했다. 큰 탐색을 새로 만드는 대신 이미 등록된 소수 대조를 마친 뒤 정확도와 비용을 함께 판단한다. 새 원격 저장소 생성, push, 업로드는 수행하지 않는다.

[scikit-learn의 중첩 평가 설명](https://scikit-learn.org/1.7/auto_examples/model_selection/plot_nested_cross_validation_iris.html)은 선택 자료와 평가 자료의 분리가 필요한 이유를 설명한다. 여기서는 과거 특징 설계의 노출과 기록 공유가 남아 있으므로 중첩 구조를 완전 미관측 평가라고 확대하지 않는다. [XGBoost3.0.5의 예측 설명](https://xgboost.readthedocs.io/en/release_3.0.0/prediction.html)과 [ExtraTrees1.7.2의 확률 열 정의](https://scikit-learn.org/1.7/modules/generated/sklearn.ensemble.ExtraTreesClassifier.html)를 실제 모델의 classes_·출력 차원 검사와 함께 대조했다.

활동 구간은 [별도 고정 기록 대조](../experiments/active_record_control/PLAN.md)에서 직접8클래스 XGB400으로 검사한다. 초기창 결과를 활동 구간으로 확대하지 않기 위한8회 진단이며 v10–v13의 개선 후보 선택은 바꾸지 않는다. [추가 CPU 비용 계획](../experiments/continuation_cost/PLAN.md)은 같은 학습 규모의 대표 모델끼리 비교한다.

## 인계 후 완료 상태

v10 18fit 복원·분할·scaler·선택 규칙 검증, v11 3fit, v12 기존6모델·18참조 해시 및 가중치 검증, v13 6fit·54참조 파일 검증을 완료했다. 활동구간의905·25특징 대조16fit와 공통 RMS8fit도 각각 CPU 복원·전체 클래스·확률 열·독립 분할·scaler·정수 지표 검증을 통과했다. v10 선택에는 정확도 이득이 없었고 성분 제거와 숲 후보는 개선에 실패했다. RMS 대조는 기록 전이를 해소하지 못했다.

기록 분리의 클래스별 혼동·예측 분포를 모두 집계했고 단일 클래스만 출력하는 붕괴는 발견하지 못했다. 현재 자료에서64학습 목표가64개 사람×조건 기록과 일대일이라는 점을 주해석에 반영했다. 비용8조건과 RMS4조건은 원시 측정값에서 중앙값/p95를 재계산했고 저장 모델·특징·예측의 동등성을 확인했다. 상세 수치·남은 자료 한계는 [통합 보고](CONTINUATION_REPORT.md)를 따른다. 과거 진행 예정 문구는 당시 기록이며 이 완료 상태가 최신이다.

최종 코어·확장·선택·공통 RMS 단위검사42개가 모두 통과했다. 기존 학습을 재실행하지 않았으며, 원자료·모델·개별예측은 로컬 비공개 경로에 보존했다.
